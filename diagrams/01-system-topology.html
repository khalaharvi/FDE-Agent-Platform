FDE Agent Platform — AWS Deployment Topology

One AWS account hosts three AgentCore agent runtimes, a shared MCP Gateway, one Aurora Postgres instance holding all five schemas, and the supporting services around them. Take-away: every arrow that ends inside Aurora either carries read-only traffic or is a narrowly-scoped, audited write path — no agent runtime has a direct write route to kg.node/kg.edge/kg.commit. The only door in is the Gate Service Lambda calling the SECURITY DEFINER function hitl.merge_proposal, and only after a human has cleared the required gates.
The one invariant this diagram exists to prove: agents propose, humans dispose — only hitl.merge_proposal writes the graph. Trace the violet lines: they are the only paths that touch a write.
