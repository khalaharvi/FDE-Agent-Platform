FDE Agent Platform — Knowledge Graph Core (ERD)

The eight tables that make up the bitemporal graph store: commits, nodes, edges, their embeddings, and the source/chunk/evidence chain that grounds every fact. Take-away: nothing is ever updated in place — every change closes a row (valid_to) and inserts a new one under a new commit — and two design choices here surprise almost everyone the first time they read this schema (below).
Surprise 1 — identity vs. version kg.edge.src_key / dst_key point at kg.node.node_key — the stable identity across versions — never at node_id, which identifies one specific version. A node can be re-versioned (new node_id) without rewriting a single edge that points at it.
Surprise 2 — the HNSW indexes are partial Every vector index on node_embedding / edge_embedding / chunk is built WHERE is_current (node embeddings are further partitioned per node_type). Retired versions never enter the index — history accumulates without growing it — and a trigger keeps is_current in sync when a version is closed out.
