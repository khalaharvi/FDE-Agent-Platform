FDE Agent Platform — The Ontology

Fifteen node types, fifteen edge types (db/001_extensions_and_types.sql), both closed ENUMs — Postgres rejects an unlisted type before any application code runs. Take-away: the ontology is not a flat mesh — activity is the hub that twelve of the fifteen edge types touch directly, because "activity" is the unit of work everything else (systems, artifacts, controls, metrics, tools, people) attaches to.
Reading this diagram: every line is one edge type's legal src → dst pair, colored by the node-type family it connects. Two edge types are universal and are shown as the dashed halo instead of 15 individual spokes: evidenced_by (any node → evidence_doc) and supersedes (any node type → a prior version of itself). Arrowheads show direction.
Also worth noticing: capability has no dedicated structural edge in the shipped ontology — scan the legal-pairs table in docs/01-knowledge-graph.md and it never appears as a named src/dst. It connects to the rest of the graph only through the two universal edges. Shown dashed, off to the side, below.
